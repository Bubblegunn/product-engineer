# Format the code, plus one pricing change that is not formatting

## Summary

This branch reformats several files: line wrapping, quote style, and expanding one-line functions. Nearly all of it changes how the code looks and not what it does.

**One change is not formatting.** `src/pricing.js` now rounds stay totals down to whole cents. The commit message says "no functional change", which is wrong for this line. See below.

## Behaviour change: stay totals are now rounded down

`nightlyTotal(rate, nights)` in `src/pricing.js` used to return `rate * nights` unchanged. It now returns `Math.floor(rate * nights * 100) / 100`.

- **Whole-cent rates:** most totals come out the same. For example, 89.50 × 3 is still 268.50. Floating-point error can occasionally push a total one cent lower, because the new code floors and doesn't round to nearest. 0.29 × 100 gives 28.999999999999996 in floating point, and flooring that gives 28.99 instead of 29.00.
- **Rates with fractions of a cent:** these used to pass through unrounded and are now truncated. For example, a rate of 33.333 × 3 nights was 99.999 and is now 99.99. Rounding down always favours the guest, so totals can only stay the same or drop by up to one cent.
- **Why it matters:** this affects the amount shown for a stay. Nothing in the diff says whether it was intended, and no test covers `nightlyTotal`.

**Decision needed from the author:** either (a) keep it and move it into its own commit or PR with tests and an accurate description, or (b) revert that line to `return rate * nights;`. I recommend (a) if the intent is to avoid showing fractional cents. If so, `Math.round` is probably the better choice because it avoids the one-cent floating-point drift above. This is a suggestion, and I haven't changed the code.

## Pricing change

`src/pricing.js`, `nightlyTotal(rate, nights)`:

- Before: `rate * nights`
- After: `Math.floor(rate * nights * 100) / 100`

The new code cuts the total off at two decimal places and always rounds **down**. It does not round to the nearest cent. Checked by running it:

| rate × nights | before | after |
|---|---|---|
| 0.29 × 100 | 28.999999999999996 | 28.99 (a cent lower than the true 29.00) |
| 10.005 × 1 | 10.005 | 10 |
| 1.1 × 3 | 3.3000000000000003 | 3.3 |
| 19.99 × 3 | 59.97 | 59.97 |

- Most ordinary totals come out the same or are tidied (3.3000000000000003 becomes 3.3).
- Some totals can come out one cent lower than the exact amount, because of how floating-point numbers work.
- `nightlyTotal` is not called from anywhere else in this repository, so I could not check what the rest of the system does with the result.
- No test covers this function.

**Decision needed before merge:** either revert this line to `rate * nights` to keep the PR formatting-only, or keep it and add tests. If it stays, use proper rounding (`Math.round`) rather than rounding down, and the account manager should confirm that rounding to the cent is the intended billing rule.

## Summary

## Behaviour change: stay totals (`src/pricing.js`)

`nightlyTotal(rate, nights)` used to return `rate * nights`. It now returns `Math.floor(rate * nights * 100) / 100`.

- **What changes for the hotel:** totals are truncated (rounded down) to two decimals. Before, a total could carry extra decimals, for example a rate of 33.333 over 3 nights. Now the fractions of a cent are dropped.
- **Direction:** totals can only go down, by less than one cent per stay.
- **Possible bug:** because the code floors a floating-point product, some totals may come out one cent low. For example, `1.15 * 100` evaluates to `114.99999999999999`, so a total that should be 1.15 would become 1.14. I haven't tested this against real rates.
- **Not covered by tests:** no test exercises `nightlyTotal`.
- **Not stated as intended:** the branch doesn't say whether truncating is the intended rounding rule. Rounding to the nearest cent (`Math.round`) is the usual choice for billing.

**Decision needed before merge:** keep the rounding (and confirm floor vs. round with the hotel), or move it to a separate PR with tests and revert it here so this one is formatting only.
