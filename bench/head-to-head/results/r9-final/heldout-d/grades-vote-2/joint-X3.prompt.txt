# fetchkit v1.3.0

## Breaking change

- **The `maxItems` option is now `limit`.** If you pass `maxItems` to `fetchAll`, rename it to `limit`. The old name is no longer read, so it is silently ignored and you get the default of 100 items. The same rename applies to the default in the config.

  ```js
  // before
  fetchAll(client, { maxItems: 50 });
  // after
  fetchAll(client, { limit: 50 });
  ```

## New

- **Retry helper.** A new `withRetry(fn, retries)` function is exported. It calls `fn` and, if it throws, tries again. It stops after the first success. If every attempt fails, it throws the last error. `retries` defaults to the new `retries` config value (2), so the function runs up to 3 times in total.
  - `withRetry` is a helper you call yourself. `fetchAll` does not retry automatically.
  - It retries immediately, with no delay between attempts. It retries on any thrown error and works with synchronous functions only.

## Changed

- **Default timeout raised from 30 seconds to 45 seconds** (`timeoutMs: 45000`). If you rely on the old default, set the timeout explicitly.

## Notes

- CSV export for reports was added and then removed again during this cycle. It is **not** part of v1.3.0, and nothing changes for you compared with v1.2.0.

Read this to decide what to change in your code before you upgrade from 1.2.0 to 1.3.0. It is written for developers who integrate fetchkit.

## Summary

Version 1.3.0 contains one breaking change. The option `maxItems` is now `limit`, and the old name no longer works. Update your calls before you upgrade.

This release also raises the default timeout from 30 to 45 seconds and adds a `withRetry` helper.

## Breaking change: rename `maxItems` to `limit`

The option that caps the number of items `fetchAll` returns has a new name. The default value, 100, is unchanged.

If you still pass `maxItems`, fetchkit ignores it and returns up to 100 items.

Before:

```js
fetchAll(client, { maxItems: 50 });
```

After:

```js
fetchAll(client, { limit: 50 });
```

If you read the setting from fetchkit's config, `config.maxItems` is now `config.limit`.

## Changes to defaults

- **Longer timeout:** The default timeout is now 45 seconds (`timeoutMs: 45000`). It was 30 seconds. If your integration depends on the old value, set the timeout yourself.
- **Retry count:** A new default setting, `retries: 2`, controls how many times `withRetry` tries again after a failure.

## New: `withRetry`

`withRetry(fn, retries)` calls `fn` and, if it throws, calls it again. It stops after the first success. You can pass `retries` to override the default of 2.

With the default, `fn` runs at most 3 times: the first attempt plus 2 retries. If every attempt fails, `withRetry` throws the error from the last attempt.

```js
const { withRetry } = require('fetchkit');

const items = withRetry(() => fetchAll(client, { limit: 50 }));
```

Two limits to know about:

- **Opt-in:** `fetchAll` does not retry on its own. Wrap your call in `withRetry` to get retries.
- **Synchronous only:** `withRetry` does not wait for a promise. If `fn` returns a promise that later rejects, `withRetry` does not retry it.

## Not in this release

- **CSV export:** We added CSV export for reports during this cycle and then removed it before release. Version 1.3.0 has no CSV export. The README sentence "Supports CSV export of reports" is wrong, and we will correct it.

# fetchkit 1.3.0 release notes

Version 1.3.0, released 14 August 2026. This document tells developers who integrate fetchkit what changed since 1.2.0 and what to do before upgrading.

## Overview

Version 1.3.0 contains one breaking change. The `maxItems` option is now called `limit`. If you pass `maxItems`, rename it before you upgrade, or fetchkit will ignore it and return every item.

The release also adds a `withRetry` helper, raises the default timeout from 30 to 45 seconds, and adds a `retries` setting. CSV export is not part of this release.

## Rename `maxItems` to `limit`

The option that caps how many items `fetchAll` returns is now `limit`. The default config key changed the same way. The default value is still 100.

1. **Find uses:** Search your code for `maxItems`.
2. **Rename:** Replace each `maxItems` with `limit`.

Before:

```js
fetchAll(client, { maxItems: 2 });
```

After:

```js
fetchAll(client, { limit: 2 });
```

fetchkit 1.3.0 does not read `maxItems`. If you leave it in place, `fetchAll` uses the default limit of 100 and no error appears. The change is in [src/index.js, line 4](file://<WORK>/runs/[path]/repo/src/index.js#L4) and [src/config.js, line 1](file://<WORK>/runs/[path]/repo/src/config.js#L1).

## Retry failed calls with `withRetry`

The new `withRetry(fn, retries)` function calls `fn` again when it throws. It returns the first successful result. If every attempt fails, it throws the last error.

- **Default retries:** `retries` defaults to 2, so `fn` runs up to 3 times in total. You can set the default in config or pass a number as the second argument.
- **Synchronous only:** `withRetry` catches errors that `fn` throws directly. It does not wait for promises, so it does not retry an `async` function that rejects.
- **Not automatic:** `fetchAll` does not retry by itself. Wrap your call in `withRetry` where you want retries.

```js
const { fetchAll, withRetry } = require('fetchkit');

const items = withRetry(() => fetchAll(client, { limit: 50 }));
```

The code is in [src/index.js, lines 6 to 12](file://<WORK>/runs/[path]/repo/src/index.js#L6-L12).

## Check your timeout settings

The default timeout rose from 30 seconds to 45 seconds (`timeoutMs: 45000`). If you rely on the default, requests now wait up to 15 seconds longer before they time out. To keep the old behaviour, set `timeoutMs` to `30000` yourself.

## CSV export is not available

The README in this release says fetchkit supports CSV export of reports. That statement is wrong. We added CSV export during development and then removed it before release. No CSV export code ships in 1.3.0.

| Area | In 1.2.0 | In 1.3.0 | Action |
|------|----------|----------|--------|
| Result cap option | `maxItems` | `limit` | Rename in your code |
| Result cap config key | `maxItems` | `limit` | Rename in your config |

# fetchkit 1.3.0 release notes

Version 1.3.0, released 14 August 2026. This document tells developers who integrate fetchkit what changed since 1.2.0 and what to do before upgrading.

## Overview

Version 1.3.0 contains one breaking change. The `maxItems` option is now called `limit`. If you pass `maxItems`, rename it before you upgrade, or fetchkit will ignore it and return every item.

The release also adds a `withRetry` helper, raises the default timeout from 30 to 45 seconds, and adds a `retries` setting. CSV export is not part of this release.

## Rename `maxItems` to `limit`

The option that caps how many items `fetchAll` returns is now `limit`. The default config key changed the same way. The default value is still 100.

1. **Find uses:** Search your code for `maxItems`.
2. **Rename:** Replace each `maxItems` with `limit`.

Before:

```js
fetchAll(client, { maxItems: 2 });
```

After:

```js
fetchAll(client, { limit: 2 });
```

fetchkit 1.3.0 does not read `maxItems`. If you leave it in place, `fetchAll` uses the default limit of 100 and no error appears. The change is in [src/index.js, line 4](file://<WORK>/runs/[path]/repo/src/index.js#L4) and [src/config.js, line 1](file://<WORK>/runs/[path]/repo/src/config.js#L1).

## Retry failed calls with `withRetry`

The new `withRetry(fn, retries)` function calls `fn` again when it throws. It returns the first successful result. If every attempt fails, it throws the last error.

- **Default retries:** `retries` defaults to 2, so `fn` runs up to 3 times in total. You can set the default in config or pass a number as the second argument.
- **Synchronous only:** `withRetry` catches errors that `fn` throws directly. It does not wait for promises, so it does not retry an `async` function that rejects.
- **Not automatic:** `fetchAll` does not retry by itself. Wrap your call in `withRetry` where you want retries.

```js
const { fetchAll, withRetry } = require('fetchkit');

const items = withRetry(() => fetchAll(client, { limit: 50 }));
```

The code is in [src/index.js, lines 6 to 12](file://<WORK>/runs/[path]/repo/src/index.js#L6-L12).

## Check your timeout settings

The default timeout rose from 30 seconds to 45 seconds (`timeoutMs: 45000`). If you rely on the default, requests now wait up to 15 seconds longer before they time out. To keep the old behaviour, set `timeoutMs` to `30000` yourself.

## CSV export is not available

The README in this release says fetchkit supports CSV export of reports. That statement is wrong. We added CSV export during development and then removed it before release. No CSV export code ships in 1.3.0.
