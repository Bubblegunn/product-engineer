I removed `--legacy-cache` and the code behind it, and committed the change as `6583c00`. All 11 tests pass.

## What changed
- **Code:** `Cache` in `tidepool/cache.py` no longer has a `legacy` option. `Cache.key` now takes only the file content, because the path argument existed only for legacy keys. `tidepool/cli.py` drops the flag. `tidepool/config.py` drops the `legacy_cache` default and the `TIDEPOOL_LEGACY_CACHE` check.
- **Config and scripts:** I removed `legacy_cache` from `config/default.json`. `scripts/nightly.sh` no longer passes the flag, and `scripts/ci.sh` no longer sets the variable.
- **Docs:** `docs/cli.md` and `docs/configuration.md` no longer mention it. `CHANGELOG.md` has a new entry under "Unreleased". I left the 0.3.0 entry as history.
- **Tests:** I deleted the two legacy tests. I also made the content-key test stricter: different content must now give a different key.

## Things to know
- **Behaviour change:** Anyone who still sets `TIDEPOOL_LEGACY_CACHE=1` or passes `--legacy-cache` will now get an error for the flag. The variable is silently ignored.
- **Left out of the commit:** Your uncommitted `README.md` edit and the `scratch/` folder.

FINAL ANSWER
I removed legacy cache mode and committed it as `7007644`. All 11 tests pass.

- **Code:**
  - `--legacy-cache`, the `legacy_cache` config key and the `TIDEPOOL_LEGACY_CACHE` env var are gone.
  - `Cache` no longer takes a `legacy` argument.
  - `Cache.key()` now takes only the content (`key(content)` instead of `key(path, content)`), since the path was only used by legacy mode.
- **Tests:** I deleted the two legacy tests. I also tightened the content-key test so it checks that different content gives a different key.
- **Docs and scripts:** I removed the flag and env var from `docs/cli.md`, `docs/configuration.md`, `scripts/ci.sh` and `scripts/nightly.sh`. I added an Unreleased entry to `CHANGELOG.md`.
- **Left out of the commit:** your uncommitted `README.md` edit and `scratch/`.

`scripts/nightly.sh` was still passing `--legacy-cache`, so something was using it. That script now uses content-hash keys, so its cache at `/var/cache/tidepool` will start cold. Any old path-keyed entries there are now orphaned and can be deleted. The old flag would also now be rejected as unknown, so check for any other callers outside this repo.
