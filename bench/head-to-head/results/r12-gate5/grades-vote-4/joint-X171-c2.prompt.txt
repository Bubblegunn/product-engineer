CRITERIA
1. Every place that sets a timeout value now holds a millisecond value: the default in pingbox/config.py is 30000 (or equivalent), and pingbox.json, Dockerfile, docker-compose.yml, .github/workflows/ci.yml and scripts/smoke.sh no longer carry the old seconds numbers (30, 5, 10) in a slot that is now read as milliseconds; if a setting is renamed (for example PINGBOX_TIMEOUT_MS), all those files use the new name consistently.
2. The actual waiting time is unchanged: pingbox/client.py (urlopen), pingbox/health.py (socket.create_connection) and pingbox/worker.py (deadline) convert milliseconds back to seconds, so a default config still waits 30 seconds and not 30000 seconds or 30 ms. The assistant's tests or final answer show this for all three modules, not only client.py.
3. Values that must stay in seconds are untouched: backoff_seconds and cache_ttl_seconds keep their names and values, and pingbox/retry.py and the retry backoff sleep in pingbox/worker.py are still seconds.
4. Documentation and user-facing text match the new unit: README.md, docs/configuration.md, docs/runbook.md (the 'raise to 60' advice) and the --timeout help text in pingbox/cli.py say milliseconds with correct numbers, and CHANGELOG.md has an entry that flags the unit change as breaking for existing deployments. FINAL ANSWER
The request timeout is now in milliseconds with a default of 30000, and all 12 tests pass. I haven't committed anything.

It wasn't only read in `config.py`. `client.py`, `health.py` and `worker.py` use it too, and `cli.py` exposes it as `--timeout`.

- **Code:**
  - `config.py` has `DEFAULT_TIMEOUT = 30000`.
  - `client.py` and `health.py` divide by 1000 before passing the value to `urlopen` and `create_connection`.
  - `worker.py` converts the deadline from milliseconds to seconds.
  - The `--timeout` help text says milliseconds.

This is a breaking change for anyone with an existing `PINGBOX_TIMEOUT=30` or `--timeout 10` set. After the change, that means 30 ms or 10 ms, and nothing warns them. If you'd like a guard for that, say so and I'll add one.
