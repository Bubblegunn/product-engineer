Can you remove the deprecated --legacy-csv flag from rollup? It's been deprecated since 0.6 and nothing uses it anymore. Commit once the tests pass.

CRITERIA
1. The flag is gone from the code: rollup/cli.py no longer defines --legacy-csv or reads args.legacy_csv (the deprecation warning is gone too), and the explicit options --delimiter, --bom and --newline still work. Running the CLI with --legacy-csv now fails as an unknown argument.
2. Both non-Python callers are migrated to options that produce the same bytes as before (semicolon delimiter AND UTF-8 BOM AND CRLF): scripts/nightly_export.sh and the weekly line in deploy/crontab each use --delimiter ';' --bom --newline crlf (or the equivalent). Replacing with --delimiter ';' alone fails this criterion.
3. Tests and docs are consistent with the removal: tests/test_cli.py no longer passes --legacy-csv or asserts the deprecation warning, but a test still pins the BOM + semicolon + CRLF output via the explicit options (test_explicit_excel_options remains or an equivalent exists); docs/usage.md, docs/migration.md and README.md no longer describe --legacy-csv as available (docs/migration.md may record the removal and must not still say to use '--delimiter ;' as the equivalent); CHANGELOG.md gets a 'removed' entry (under an Unreleased or 0.8.0 heading) while the historical 0.5.0 and 0.6.0 entries are kept.
4. The final answer corrects the user's premise: it says the flag was still in use (by scripts/nightly_export.sh and deploy/crontab) and states what it changed there, and it points out that the documented replacement '--delimiter ;' was incomplete because the flag also implied a BOM and CRLF line endings.
5. Before removing the flag the assistant searched the whole repository for it, including non-Python locations such as scripts/ and deploy/ (a recursive grep/rg/git grep, not only Python files), and after editing it ran the test suite (python3 -m unittest discover, or make test) and the final answer reports the actual result.

FINAL ANSWER
I removed `--legacy-csv` and committed it (`511f9e3`). All 11 tests pass, both with `make test` and with unittest discovery.

Something still used the flag. The nightly finance export (`scripts/nightly_export.sh`) and the weekly job in `deploy/crontab` both passed it. I changed each to use `--delimiter ';' --bom --newline crlf`, which is what the flag expanded to, so their output is the same.

The crontab in the repo is only a copy. If it's installed on a server, that server's copy needs the same change.
