# logslice 1.5.0 (draft)

## ⚠️ Action required if you set the timezone with an environment variable

The `LOGSLICE_TZ` environment variable has been renamed to **`LOGSLICE_TIMEZONE`**. `LOGSLICE_TZ` is no longer read.

If your cron jobs or wrapper scripts set `LOGSLICE_TZ`, update them before upgrading. If you don't, logslice will not error. It will silently fall back to the `timezone` value in `logslice.config.json` (or the default), so timestamps in your output could shift.

```
# before
LOGSLICE_TZ=Europe/Berlin logslice app.log --since 2h
# after
LOGSLICE_TIMEZONE=Europe/Berlin logslice app.log --since 2h
```

Setting `timezone` in `logslice.config.json` is unaffected.

## New

- **JSON output (`--json`).** Prints one JSON object per line, each with `ts`, `level` and `msg`. It's meant for piping into `jq` or a log shipper. It works with `--level`, `--since` and `--until`. Without `--json`, output is the same readable text as before.
- **Follow mode (`--follow`) — experimental.** Keeps running and prints new matching lines as they're appended, like `tail -f`. It's off by default. To try it, add this to `logslice.config.json`:
  ```json
  { "experimental": { "follow": true } }
  ```
  Without that setting, `--follow` exits with an error that says how to enable it. It's experimental, so its behavior may change in later releases. Don't rely on it in production cron jobs yet.

## Fixed

- **`--level` is now case-insensitive.** `--level error` now matches `ERROR`, `Error` and `error` lines. Before, it only matched the exact case you typed.

Setting `timezone` in `logslice.config.json` is unaffected.

- **`--follow` (experimental).** Keeps watching the file for new lines, like `tail -f`, and applies your `--level`, `--since` and `--until` filters. It is off by default. To try it, add `"experimental": { "follow": true }` to `logslice.config.json`. Without that, logslice exits with an error that says so. # logslice release notes: changes since v1.4.0

**Purpose:** Tells you what changed since v1.4.0 and what to check in your cron jobs before you upgrade.
**For:** People who run logslice from cron jobs and scripts.
**Version and date:** [Author needed: version number and release date]

## Overview

Check one thing before you upgrade: the environment variable that sets the timezone has a new name. If your jobs set `LOGSLICE_TZ`, rename it to `LOGSLICE_TIMEZONE`. The old name is now ignored without any warning, and logslice prints times in UTC instead.

Three other changes are safe to adopt:

- **JSON output:** `--json` prints one JSON object per line.
- **Case-insensitive levels:** `--level error` now matches `ERROR`.
- **Follow mode (experimental):** `--follow` is off by default.

## Rename `LOGSLICE_TZ` to `LOGSLICE_TIMEZONE`

The timezone variable is now `LOGSLICE_TIMEZONE`. logslice no longer reads `LOGSLICE_TZ`.

If you set the old name, logslice does not report an error. It falls back to the `timezone` value in `logslice.config.json`, or to `UTC` if that file does not set one. Your output keeps working, but the times may be wrong.

To update your jobs:

1. Search your crontab and scripts for `LOGSLICE_TZ`.
2. Replace each one with `LOGSLICE_TIMEZONE`, keeping the same value (for example `Europe/Berlin`).
3. Run one job by hand and check that the times match your timezone.

The `timezone` setting in `logslice.config.json` has not changed.

## Read results as JSON with `--json`

Add `--json` to print each matching line as one JSON object. Each object sits on its own line, so you can pipe the output to a tool such as `jq`.

```
logslice --json --level error app.log
```

Each object has three fields: `ts`, `level` and `msg`. Their values are copied from the log line as written. In JSON mode, logslice does not convert the time to your timezone and does not change the case of the level.

Without `--json`, the output is the same human-readable text as before.

## Match levels in any letter case

`--level` now ignores letter case. `--level error` matches lines marked `ERROR`, `Error` and `error`.

Check any job that relied on the old behaviour. If your logs contain the same level in different cases, a filter that used to match only one spelling now matches all of them, and your output may contain more lines.

## Try `--follow` (experimental)

`--follow` keeps logslice running and prints new matching lines as they are added to the file. It starts at the end of the file, so it does not print existing lines.

Because this feature is experimental, it is off by default. If you run `--follow` without enabling it, logslice stops with an error that explains how to enable it. To turn it on, add this to `logslice.config.json`:

```json
{
  "experimental": {
    "follow": true
  }
}
```

logslice reads this file from the directory where you run the command. In a cron job, change to the right directory first.

Do not rely on `--follow` for important jobs yet. Its automated test is switched off because it fails unpredictably, and its behaviour may change in a later release. A job that runs `--follow` also never finishes by itself, so it does not suit most cron jobs.

## Where to find more

- **Usage:** `docs/usage.md` lists all options.
- **Settings:** `docs/configuration.md` describes `logslice.config.json`.

## New: print each line as JSON

Add `--json` to print one JSON object per line instead of text. Use it when another tool reads the output.

```
logslice --level ERROR --json app.log
```

Each object has three fields:

- **`ts`:** the timestamp exactly as it appears in the log line. logslice does not convert it to your timezone.
- **`level`:** the level exactly as written in the log, for example `ERROR`.
- **`msg`:** the rest of the line.

logslice prints each line as it reads it, so large files do not fill memory.

## Fixed: `--level` ignores letter case

`--level error` now matches lines marked `ERROR`, `Error` or `error`. Before this fix, a lowercase value matched nothing and printed no output, with no error.

## New and experimental: follow a log with `--follow`

`--follow` keeps running and prints new lines as they are added to the file, similar to `tail -f`. It works with `--level`, `--since`, `--until` and `--json`.

This feature is experimental, so it is off by default and its behaviour may change. To turn it on, set this in `logslice.config.json`:

```json
{
  "experimental": {
    "follow": true
  }
}
```

Then run `logslice --follow app.log`. Without the setting, logslice stops with a message that explains how to turn the feature on.

Keep these limits in mind:

- **Do not use it in cron.** It never exits on its own, so a scheduled job that runs it will pile up.
- **New lines only.** It skips what is already in the file when you start it.
- **Config location.** logslice reads `logslice.config.json` from the current directory, so start it from the directory that holds the file.

# logslice release notes: changes since 1.4.0

Read this before you upgrade logslice from 1.4.0. It lists what changed and what to check in your cron jobs.

- **Version:** [Author needed: new version number]
- **Date:** [Author needed: release date]
- **Reader:** People who run logslice in scheduled jobs and scripts.

## Overview

**Action required:** One change can break existing jobs. The `LOGSLICE_TZ` environment variable is now `LOGSLICE_TIMEZONE`. If your jobs set `LOGSLICE_TZ`, rename it before you upgrade.

The other changes are optional or only make logslice more forgiving:

- **Level filter:** `--level` now ignores upper and lower case.
- **JSON output:** New `--json` option prints one JSON object per line.
- **Follow mode:** New `--follow` option, experimental and off by default.

## Rename LOGSLICE_TZ to LOGSLICE_TIMEZONE

logslice no longer reads `LOGSLICE_TZ`. It reads `LOGSLICE_TIMEZONE` instead. The name `timezone` in `logslice.config.json` has not changed.

If a job still sets `LOGSLICE_TZ`, logslice ignores it without an error. Your output then uses the timezone from `logslice.config.json`, or the default, which may differ from what you set.

To fix a job, change the variable name in your crontab or script:

```
# Before
LOGSLICE_TZ=Europe/London logslice app.log

# After
LOGSLICE_TIMEZONE=Europe/London logslice app.log
```

## Match levels in any case

`--level` now matches a level whatever its case. Before, `--level error` skipped lines that were logged as `ERROR`. Now `--level error`, `--level ERROR` and `--level Error` all give the same result.

You do not need to change anything. If you worked around the old behaviour by writing the level in capitals, that still works.

## Print log lines as JSON

Add `--json` to print each matching line as one JSON object on its own line. This suits scripts and tools such as `jq`, because each line can be read on its own.

```
logslice --level error --json app.log
```

Each object has three fields:

- **`ts`:** The timestamp, copied as it appears in the log. logslice does not convert it to your timezone.
- **`level`:** The level, written as it appears in the log.
- **`msg`:** The rest of the message.

Without `--json`, the output is the same readable text as before.

## Try follow mode (experimental)

`--follow` keeps running and prints new matching lines as they are added to a file. It works like `tail -f` and accepts the same filters, including `--json`.

Follow mode is experimental, so it may change or be removed in a later release. It is off by default. logslice stops with an error if you use `--follow` without turning it on.

To turn it on, add this to `logslice.config.json`:

```json
{
  "experimental": {
    "follow": true
  }
}
```

Keep these points in mind:

- **Not for cron jobs:** `--follow` never finishes on its own. Use it in a terminal or a service, not in a job that must end.
- **Config location:** logslice reads `logslice.config.json` from the directory it runs in. Cron often starts in your home directory, so check the path.
- **Only new lines:** It prints lines added after it starts, not lines already in the file.
- **Log rotation:** It does not handle rotated or truncated files. Restart it after your logs rotate.
