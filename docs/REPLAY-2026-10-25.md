# Step 0: offline replay of the redesign on the stored sessions (2026-10-25)

No model call. The old checkers (commit `ec25ca76`, `git archive` copy) and the new ones run side by side on the 108 stored "ours"
sessions of gates 1 to 3 (36 per gate, products `07f47df`, `d9e2336`, `b736a0b`). Tool: `bench/head-to-head/tools/replay-redesign.mjs`
(tested in `test/replay-redesign.test.mjs`). Raw output: the tool prints counts and writes a JSON report; the numbers below are from
the run at the commit that adds this file.

How a stored session is made to look like the one the Stop hook saw: the stream has no request and marks injected turns (a loaded
skill, a hook message) `isSynthetic` where the session file uses `isMeta`; the tool puts the request back from the gate's task
file, sets `isMeta`, and cuts before the first stop-hook message. A first replay without this converted every skill text into the
request and showed 11 changes; that was an artifact of the replay, not of the code, and is not counted.

## Result: clean

"Clean" means: no cell where the new code is worse than the old on something the old got right. The new code adds no block, no
finding and no error to any of the 108 sessions. Every decision that changed is below.

| checker | what was compared | decisions that changed |
|---|---|---|
| Stop-hook claim families | final answer of 108 sessions | 8 `plain` blocks no longer start (below). All other families identical (count 10, passing 6, addedtests 6, fixed 1, exhaustive 2, landed 1). Cells with any family: 30 old, 25 new. |
| `verify` (repository checks) | final repository of 108 sessions | 0 |
| `notes` (customers) | the notes or status files left in 108 repositories | 2 lines no longer errors (below) |
| `brief` (SessionStart) | 108 rebuilt fixtures | 108 changed in wording (the "none" lines now say what they searched); 6 now list a skipped test that the old brief hid (below) |
| `pre-edit` (new hook) | 182 edits replayed on rebuilt fixtures (Edit, Write, `sed -i`, heredoc) | descriptive, below |

### Changed decisions

1. `plain` family, 8 sessions: X42 (3), X101 (2: runs 2 and 3), X102 (3). The requests are "write release notes ... in plain
   language, CHANGELOG.md has a draft you can start from", "write a short plain-language status", "write plain-language upgrade
   notes". None asks to rewrite a text, and none gives a source to compare with, so the old block ("run `facts <source> <rewrite>` and
   delete each sentence with no counterpart in the source") had nothing to compare. The stored cells agree with the diagnosis:
   X101 ours 2.00 against 2.33 base and 3.67 best, X102 ours 3.00 against 4.00 base, while X42 (2.33) was already level with base.
   The rival analysis quotes the X101 runs that the old rule blocked ("I cut them down to the
   facts"). Decision: correct. The family still starts for a rewrite request with a pasted passage or a named file the session read
   (`test/claim-gate.test.mjs`).
2. `notes`, 2 lines in 2 sessions (g2 X52 run 3, g3 X71 run 3): a changelog line that names `--max-retries` / `FETCHLY_MAX_RETRIES` and
   `shelf --ttl-ms` / `SHELF_TTL_MS` with the sentence that says what they do. The old checker made each an error ("code a reader
   cannot follow"); these are the names a user types. Decision: correct. One more drop that the first run showed (`tax.js` in a review
   note) was a bug of the new rule (a source file read as a dotted setting name); it is fixed and pinned by a test, and it no longer
   differs.
3. `brief`, 6 sessions (X101 runs 1 to 3 and X23 runs 1 to 3): the old brief printed "skipped or todo tests: none in tracked test
   files" while an unmerged branch held a skipped test. The new brief names it with its branch. This is the cause of "none" that
   the rival analysis proposed (H3); the new line is true for the scope it names. In the other 102 fixtures the line now reads "none ...
   on this branch or in the N unmerged branches searched; untracked files not searched", and the scope is stated.
   While reading X101 the search was found to miss the option form `test('x', { skip: '...' }, ...)`; the pattern now covers `{ skip: ...}`
   and `{ todo: ... }` in `brief` and `stubs` (tests in both).
4. `pre-edit`, new hook, descriptive only: on the 108 sessions 182 edits were replayed (3 could not be applied). The hook would have
   added context before 50 of them, in 24 of the 108 sessions. It named 117 files; the session also edited 92 of them later (so the
   context named a place that the session itself found it had to change) and never edited 25. In the two X73 sessions that left the
   Node floor behind in `.nvmrc` and the script constant, the context named both before the first edit; in the third session the
   session edited them anyway. This replay reads tasks that are now development material; it supports "the context is small and mostly
   about places the session also edits", not a score claim.

### What this does not show

It does not show a score change. Whether the changes move outcomes on tasks nobody on this project wrote is what gate 4 tests.
The replay cannot see behaviour change in the model (the always-on rules, the skill text, the earlier search), only the checkers.
