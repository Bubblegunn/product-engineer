### 1.1 Where ISO does NOT compete with us (do not over-learn)
- It never reads a diff, a commit, a git range or a number. Nothing detects a false claim (`bin/diff.mjs`, `claims.mjs`, `range.mjs`, `stubs.mjs`, `twins.mjs`, `claim-gate.mjs` are all ours alone).
- Its thresholds are "this project's own proxy" (`README.md:97`), not a standard clause. Its README forbids a compliance claim (`README.md:91-99`). Match that candour in any rule we copy.
- Gate never fails on findings (advice only, `audit-pull-request-text.sh:11-14`). Ours fails on a missing block. Do not make prose rules blocking.

## 3. Ranked: 8 most worth adopting from iso-24495

All MIT, so code may be adapted with the notice in our `THIRD_PARTY_NOTICES.md` (same path we used for dod-guard and smart-commits, `stubs.mjs:7-10`, `diff.mjs:16-18`).

1. Ambiguity-aware sentence segmenter + sentence-length / average / paragraph rules run on the customer block and PR body, with line numbers (`parse.ts:1102-1360`, `audit-corpus.ts:954-1010`). Needs: our own abbreviation/title set, a split/merge/ambiguous classifier, two counts (most and fewest sentences), a minimum-sample guard (>= 10), thresholds as one frozen object, tests on e.g./Dr./J. Smith/versions like 1.2.3/URLs.
2. Named-not-used exemption (`audit-corpus.ts:758-765`). Needs: blank out `` `x` ``, "x", 'x' spans equal to the matched term before matching. Prerequisite for every lexicon rule below; without it the rule flags its own explanation.
3. filler-opening on the first sentence of the customer block and PR body (`lexicon.ts:1036-1041`, `audit-corpus.ts:809-839`). Needs: strip `*_\`` and smart quotes, whole-word boundary, skip "not ..." remainder, a list tuned to agent openers ("Certainly", "Here's a summary", "This PR ...").
4. Exact-phrase lexicon bundle: wordy-phrase (24), doublet (17), complex-word, double-negative (15) (`audit-corpus.ts:123-181`, `lexicon.ts:1004-1056`). Needs: longest-phrase-wins overlap, `\s+` between words, per-rule `--lang en` gate, a count of false positives on a real corpus before turning on (rule 8). Warnings only.
5. Minimal Markdown reader: skip fenced and indented code, front matter, tables, quotes, strip list markers, `frontMatter:false` for PR bodies (`parse.ts:1-12,31-37,1032`). Needs: a line-state machine of about 120 lines, a differential test against 20 hand-picked bodies (ISO used 302 reference documents, `README.md:130`). Do not port the 1,362-line parser.
6. Report-trust proof and exit-code taxonomy (`description-report.ts:28-59`, `audit-pull-request-text.sh:12-21,34-45,116-126`). Needs: `check --pr` and the Action assert the text they examined is the fetched body (non-zero length, same hash), distinguish "nothing to check" from "check did not run", and use `--` before file arguments in our shell scripts.
7. acronym-undefined for terms outside our jargon table (`audit-corpus.ts:396-520`, allowlist `:934-947`). Needs: all-caps token shape 2-6 letters, a "words (ACR)" definition window of <= 6 preceding words, a shout test via a small common-word set built from our own commits (not ISO's 7,435-word list), `knownTerms` in `.product-engineer.json`.
8. link-text and image-alt on PR bodies (`audit-corpus.ts:608-752`). Needs: inline, reference and HTML forms; "decorative" title opt-out; the reader from item 5 so code fences do not match. About 60 lines.

Test method to carry over with all of them: adjudicate expected results before running (`tests/fixtures/known-good/SOURCES.md:12`), fuzz inputs and a size budget (`robustness.test.ts:1-30`), and a mutation check per new test (`README.md` "Testing policy").
